# СПЕЦИФИКАЦИЯ ОПЕРАЦИОННОЙ СИСТЕМЫ «ИрНа»

Версия документа: 0.2 (утверждена базовая конфигурация)
Дата: 2026-10-19
Статус: решения заказчика зафиксированы (см. DECISIONS.md D-008…D-012)

**Имя ОС:** все упоминания имени — только через `branding.md` (реестр мест
использования имени). Имя легко переименовывается перед релизом.

---

## 1. ЦЕЛЬ ПРОЕКТА

Создать настольную операционную систему для ПК x86-64 с графическим
интерфейсом, визуально похожим на Windows 10, написанную полностью с нуля.

**Юридическая основа (принцип «чистой комнаты»):**
- Не используется код Microsoft (Windows, WDK, заголовки Windows API как источник кода).
- Визуальные паттерны (панель задач, «Пуск», окна с кнопками свернуть/развернуть/закрыть) — не охраняются авторским правом, их можно воспроизводить.
- ЗАПРЕЩЕНО: копировать логотипы, звуки (startup sound), шрифт Segoe UI (вместо него — свободный шрифт, например PT Sans / DejaVu Sans), иконки из Windows.
- Разрешено: open-source компоненты с лицензиями MIT / Apache-2.0 / BSD / LGPLv3 (с динамической линковкой).

## 2. ЦЕЛЕВАЯ ПЛАТФОРМА

| Параметр | Значение |
|---|---|
| Архитектура | x86-64 (UEFI + legacy BIOS загрузка на этапе MVP) |
| Мин.Requirements | 2 CPU ядра, 2 ГБ RAM, 16 ГБ диск, VGA-совместимый фреймбуфер |
| Тестовая среда | QEMU/KVM на основном ПК (Lenovo, AMD A10-7800B, 8 ГБ RAM, Windows 10 + WSL2 или Linux-дистрибутив в Hyper-V/WSL2) |
| Реальное железо | Откладывается до этапа M4 |

EXE-совместимость (Win32/PE-loader) — вне скоупа MVP, рассматривается в Phase 2.

## 3. АРХИТЕКТУРА И ЯЗЫКИ (итоговое решение)

```
┌─────────────────────────────────────────────┐
│  ПРИЛОЖЕНИЯ (C++ / Qt)                       │  user space
│  Блокнот, Медиаплеер, Файловый менеджер     │
├─────────────────────────────────────────────┤
│  DESKTOP SHELL (C++ / Qt)                   │  user space
│  Панель задач, Меню «Пуск», Окна, Обои      │
├─────────────────────────────────────────────┤
│  WINDOW SERVER (собственный, C++)           │  user space
│  Композитор, ввод (мышь/клавиатура), IPC    │
├─────────────────────────────────────────────┤
│  СИСТЕМНЫЕ СЕРВИСЫ (Rust)                   │  user space
│  init(1), logd, devd, сетевой стек          │
├─────────────────────────────────────────────┤
│  СИСТЕМНЫЕ ВЫЗОВЫ + LIBC (Rust/C)           │  граница kernel/user
├─────────────────────────────────────────────┤
│  ЯДРО (Rust, no_std)                        │  kernel space
│  Планировщик, память, драйверы, ФС          │
├─────────────────────────────────────────────┤
│  BOOTLOADER (Rust/C, лимит UEFI)            │  firmware -> kernel
└─────────────────────────────────────────────┘
```

Обоснование выбора:
- **Rust для ядра:** безопасность памяти на этапе компиляции, экосистема `no_std`
  (crates: `limine`/`uefi-rs`, `x86_64`, `volatile`), готовые учебные проекты
  (Ardanis/OS-From-Scratch, rCore).
- **C++/Qt для GUI:** Qt под LGPL — можно использовать без передачи исходников
  своего приложения при динамической линковке. Аналог окон Windows 10 делается
  быстро: `QMainWindow`, frameless windows + собственная отрисовка заголовка.
- **Python исключён** из системных слоёв (GIL, интерпретатор, сборщик мусора —
  неприемлемы для ОС).

### 3.1 Ограничение: минимум стороннего кода
- Ядро: только `no_std`-крейты, никаких зависимостей с C-рантаймом.
- Window server: пишется СВОЙ (не X11/Wayland/compositor) — решение заказчика
  2026-10-19 (D-010). Qt допускается использовать ТОЛЬКО внутри приложений и
  shell, они общаются с window server по своему протоколу.

## 4. КОМПОНЕНТЫ — ДЕТАЛЬНАЯ РАЗБИВКА

### 4.1 Загрузчик (Bootloader)
- UEFI-загрузчик на Rust (`uefi-rs` crate, MIT). Загружает образ ядра в память,
  передаёт таблицу памяти (E820/UEFI memory map), фреймбуфер GOP/LFB.
- MVP-альтернатива: Grub2/Limine (внешние, не наш код) — допустимо, т.к. GPL
  загрузчика не «заражает» ядро (загрузка ≠ линковка).
- Критерий готовности: экран «ИрНа booting...» → прыжок в ядро.
  (Текст берётся из `bootloader/config.toml`, не хардкод — см. branding.md B2.)

### 4.2 Ядро (Kernel, Rust)
Подсистемы и порядок реализации:
1. **Ранний старт:** GDT/IDT, прерывания PIC/APIC, serial console (вывод логов в QEMU).
2. **Память:** физический аллокатор (buddy/frame), виртуальная память (4-level paging), kmalloc.
3. **Планировщик:** приоритетный вытесняющий (MVP: round-robin 2 уровня), многозадачность (threads/processes).
4. **Системые вызовы:** syscall/sysret ABI. Минимальный набор:
   `read, write, open, close, seek, mmap, munmap, fork/execve, wait, exit, getpid, ioctl`.
5. **Драйверы MVP:** VGA text → framebuffer (dispi/BOCHS VBE), PS/2 клавиатура+мышь,
   PIT/HPET таймер, ATA/AHCI диск, e1000 сеть (позже).
6. **ФС:** свой простой journaling-free ФС (аналог FAT-подобного) ИЛИ tmpfs на MVP;
   чтение ext2 (реализация своя, по опубликованному формату — формат не объект АП).
7. **Процессы и ELF-загрузчик:** запуск statically-linked ELF-бинарников из ФС.

Критерий готовности ядра: `hello.txt` читается с диска, запускается 2 процесса,
логи пишутся на serial.

### 4.3 Системные сервисы (Rust, user space)
- `init` (PID 1): монтирует /dev /proc-lite, запускает winserv, shell, sesid.
- `logd`: кольцевой буфер логов + запись на диск.
- `devd`: hot-plug уведомления (позже).

### 4.4 Window Server (C++, свой)
- Модель: клиент-сервер, Unix-socket IPC, бинарный протокол сообщений
  (вдохновлён идеей Wayland, но реализация своя — ~3–5 тыс. строк).
- Обязанности: композитинг (склейка поверхностей в один фреймбуфер),
  маршрутизация ввода (фокус окна), клипборд, глобальный хоткей Ctrl+Esc.
- Протокол (пример сообщений): `CREATE_SURFACE(w,h,fmt)`, `PRESENT(shm_id,damage)`,
  `EVENT_POINTER(x,y,btn)`, `EVENT_KEY(scancode,pressed)`, `SET_TITLE`, `MOVE_RESIZE`.

### 4.5 Desktop Shell (C++/Qt) — «как Windows 10»
Элементы и поведение (спецификация визуала — только идеи, не ассеты MS):
- **Обои:** сплошной цвет/градиент «синий квадрат» (своя генерация, не bitmap MS).
- **Панель задач:** внизу, высота 48px, слева кнопка «Пуск» (квадрат из 4 клеток —
  своя отрисовка), список запущенных приложений (иконка 32px + hover-подсветка),
  справа трей (часы ДД.ММ.ГГГЧ ЧЧ:ММ, уведомления, «Показать рабочий стол»).
- **Меню «Пуск»** (tile view): левая колонка — список программ (алфавитный),
  правая — плитки 150×150px (живые плитки не в MVP). Открытие: клик или Win-key.
- **Окна:** заголовок 32px, кнопки minimize/maximize/close справа (своя отрисовка
  в стиле Fluent-like: тонкие символы ✕ ▢ —), тень,_snap_ к краям экрана (Aero Snap),
  перетаскивание за заголовок, изменение размера за края, Alt+Tab переключатель.
- **Уведомления (toast):** правый нижний угол, стек до 3 шт. — позже (M4).
- **Проводник файлов:** упрощённый (дерево + список) — M4.

### 4.6 Приложения (C++/Qt)
1. **Блокнот (Notepad-клон):** файл/редактирование/формат меню, UTF-8, перенос по словам,
   найти/заменить, размер шрифта. Без вкладок (это WordPad-функция).
2. **Медиаплеер:** воспроизведение видео через ffmpeg libraries (LGPL-компоненты,
   динамическая линковка) + own UI: play/pause/seek/speed, плейлист m3u.
   Аудио-выход через свой звуковой драйвер (HDA Intel) — самая сложная часть, M4+.
3. Позже: калькулятор, настройки (Settings-стиль tiles).

## 5. ИНТЕРФЕЙС И ЛОКАЛИЗАЦИЯ

- Системный уровень (ABI, пути `/bin`, переменные окружения, сетевые протоколы): ASCII/латиница (техническая необходимость).
- UI и пользовательские данные: полный русский (UTF-8), шрифт PT Sans (OFL — свободно).
- Раскладка: EN+RU, переключение Win+Space и Alt+Shift.
- Терминология: свои названия («Проводник» допустимо как общеупотребительное слово, но лучше «Файлы»; «Параметры» → «Настройки»).

## 6. ЭТАПЫ И ДОРОЖНАЯ КАРТА (без строгих сроков, ориентир — часы)

| Этап | Содержание | Результат | Оценка |
|---|---|---|---|
| **M0** | Инструменты: WSL2/Linux + rustup + LLVM/clang + Qt6 + QEMU. Hello-world в ядре (serial print) | QEMU показывает строку от ядра | 1–2 нед |
| **M1** | Ядро Rust: память, прерывания, планировщик, syscall, framebuffer, PS/2 | Чёрный экран с текстом, работает клавиатура | 1–2 мес |
| **M2** | ELF-загрузка, ФС (tmpfs/ext2), init, процесс-менеджмент | Запускаются 2 юзер-процесса | 1–2 мес |
| **M3** | Window server + первый вывод окна из C++ клиента | Окно двигается мышью | 2–3 мес |
| **M4** | Qt-приложение в нашем окне (plug via shm surface), панель задач, «Пуск» | Рабочий стол «как Win10», блокнот открывается | 2–4 мес |
| **M5** | AHCI-диск, хранение файлов, медиаплеер (без звука→со звуком) | Полноценное использование | 2–4 мес |
| M6+ | Сеть, звук, Bluetooth, EXE-эмуляция (отдельное решение), реальное железо | Экосистема |будущее |

**Важно про Qt напрямую:** Qt требует либо XCB/Wayland backend, либо plugin под
наш window server. План: в M4 пишем минимальный Qt platform plugin (QPA) для
нашего протокола (~1–2 тыс. строк C++). Это известный путь (есть примеры qpa
для framebuffer: `qtbase .../eglfs`, `linuxfb`).

## 8. КАК МЫ РАБОТАЕМ (против потери контекста)

1. Каждый архитектурный выбор — запись в `DECISIONS.md` (формат: дата, контекст, решение, последствия).
2. `ROADMAP.md` — единственный источник статуса этапов; обновляется после каждого завершённого шага.
3. Коммиты: префикс компонента (`kernel: add buddy allocator`), один смысл = один коммит.
4. Каждая сессия начинается с чтения SPEC + ROADMAP (первые 5 минут), заканчивается апдейтом ROADMAP.
5. Ветки по этапам: `m1-kernel-mem`, `m3-winserv` и т.д.
